# T-001: Asset pipeline

**Source:** [demo-spec.md](../demo-spec.md) §3, milestone 1 · **Model:** Sonnet · **Depends on:** nothing

## Why

The game draws everything from one atlas built from the dragongame BMPs, and the sim needs per-frame durations without reading files. Nothing else can be rendered until this exists.

## What

1. `tools/manifest.json`: `{ "sourceRoot": "E:/code/dragongame/assets", "entries": [...], "sounds": [...] }`. Entries cover **every** atlas name in spec §3.3 (all except `gem`, which is procedural). Use `{ "name", "list" }` for `.txt` sequences, `{ "name", "file" }` for single frames, and `{ "name", "files": [...] }` for numbered BMP ranges that have no `.txt` (`explosion.big`, `explosion.laser`, `explosion.laserbig`).
2. `tools/build-atlas.mjs` exactly as spec §3.2: own BMP decoder (8-bit palette and 24-bit, bottom-up, 4-byte row padding; also accept top-down if height is negative), key colour `(0,0,0)` → alpha 0, shelf packer with 1 px padding, PNG writer on `node:zlib` with its own CRC32, writes `assets/atlas.png`, `assets/atlas.json`, `src/sim/anims.js`. `sourceRoot` may be overridden by a `--source <dir>` argument or `DRAGONGAME_ASSETS` env var.
3. `tools/copy-sounds.mjs`: copies the 15 WAVs listed in spec §3.3 into `assets/sounds/`.
4. Run both and **commit the generated outputs** (`assets/atlas.png`, `assets/atlas.json`, `assets/sounds/*.wav`, `src/sim/anims.js`). A checkout without the asset pack must still run the game and pass the tests from the committed files.
5. Tests in `test/atlas.test.mjs`.

## Decisions already made

- `src/sim/anims.js` already exists, hand-generated by the orchestrator in the exact target format (sorted keys, one line per anim, header comment). Your build script must regenerate it; if your output differs, yours wins only where the spec says so. Keep the format so the diff is small.
- Single-frame entries (`castle`, `icon.*`) get `ticks: [6]` (spec §3.2).
- Sequence `.txt` files have CRLF line endings, blank lines, missing final newlines and trailing spaces. Split on whitespace; in FANCY files tokens are `name N` pairs.
- Frame keys in `atlas.json` are the source path relative to `sourceRoot` with forward slashes (`knight/knight0000.bmp`). A frame used by several anims is packed once.
- Atlas width: pick a fixed width (for example 512) and grow height; power-of-two not required.
- `fireball/big_fireball.txt` lists `1.bmp 2.bmp`, which are 20 px, not 12 px as spec §3.3 says. Use the file as the spec names it and correct the size note in §3.3. Same for any other size note you find wrong: fix the note, not the source.
- `golem/golem.txt` lists `golem_death0000..0006`. That is how the original works; keep it.
- The ghost knight frames live in `ghostnight/` (the `knight/` folder has copies; use `ghostnight/` as the spec says).

## Tests (`test/atlas.test.mjs`)

- BMP decoder on synthetic buffers built in the test: 24-bit with row padding (width 3), 8-bit palette, key colour becomes alpha 0.
- PNG writer round trip: write a small RGBA image, parse chunks, check CRCs, inflate IDAT, unfilter, compare pixels.
- Packer: rectangles do not overlap (including padding) and stay inside the atlas.
- Committed `assets/atlas.json`: every manifest name exists in `anims`, every anim frame exists in `frames`, every frame rect is inside the PNG size (read from the IHDR of the committed `atlas.png`), `ticks.length === frames.length`.
- `src/sim/anims.js` ticks equal `atlas.json` ticks for every name.
- `dragon.dir`, `laser.dir`, `laser.bigdir` have exactly 16 frames.
- Build from source: runs `build-atlas` into a temporary directory and compares with the committed output; **skipped** (`t.skip`) when the source folder does not exist.
- The cross-check against `content.js` `ATLAS_NAMES` is done by `npm run check` once T-002 lands; nothing to do here.
